Ce guide couvre la fonctionnalité centrale de l'API Apprise : l'envoi de notifications. Vous pouvez envoyer des notifications de deux manières :

1. **Sans état :** vous fournissez les URL de configuration dans la charge utile de la requête.
1. **Avec état :** vous référencez une clé de configuration préalablement enregistrée.

## Formats de Réponse

Par défaut, les points de terminaison renvoient `text/plain`. Si vous préférez
du JSON, envoyez `Accept: application/json`.

Pour les points de terminaison de notification (`/notify` et `/notify/{KEY}`),
vous pouvez aussi demander une vue HTML simple des journaux avec
`Accept: text/html`. C'est principalement utile pour des tests manuels dans un
navigateur.

Ces réponses attendent la fin de l'envoi des notifications, puis transmettent
les journaux une entrée à la fois. Un résultat volumineux stocké sur disque
n'est donc pas reconstruit en mémoire et le format de la réponse ne change pas.

### Diffusion en direct de la progression

Les points de terminaison de notification peuvent indiquer leur progression à mesure que chaque service est notifié. Utilisez `?stream=yes` ou envoyez `Accept: text/event-stream`.

Les éventuels événements `log` sont suivis d'un événement `result`. Une erreur inattendue produit plutôt un événement `error`.

```bash
curl -N -X POST \
  -H "Content-Type: application/json" \
  -d '{"body": "Sauvegarde terminée avec succès.", "title": "État du système"}' \
  "http://localhost:8000/notify?stream=yes"
```

```text
event: log
data: {"level": "INFO", "asctime": "2025-01-01 12:00:00,000", "message": "Sent to Telegram", "service": "Telegram"}

event: result
data: {"status": "SUCCESS"}
```

Le flux commence avec le code HTTP `200`, avant la fin de l'envoi. Consultez le statut du dernier événement `result` (`SUCCESS`, `FAILURE`, `NOMATCH`, `PARTIAL` ou `TIMEOUT`) au lieu d'attendre le code HTTP `424`.

Chaque connexion conserve jusqu'à 2 Mo de journaux en attente en mémoire. Si le
client prend du retard, jusqu'à 256 Mo supplémentaires peuvent être conservés
dans un stockage temporaire. Les événements restent ordonnés tant qu'aucune
limite n'est atteinte.

Si la limite est atteinte ou si le stockage temporaire échoue, l'envoi des
notifications continue. Le flux émet un journal `ERROR` demandant de contacter
l'administrateur du serveur. Le flux reprend les nouvelles entrées une fois les
événements stockés envoyés.

Les opérateurs peuvent modifier ces limites avec `APPRISE_STREAM_MEMORY_SIZE`
et `APPRISE_STREAM_DISK_SIZE`. Les mêmes limites empêchent aussi les journaux
du résultat final de croître sans limite en mémoire. Consultez
[Variables d'environnement](/api/reference/environment/#stockage-et-limites) pour connaître les modes utilisant la valeur zéro.

Au maximum, `APPRISE_STREAM_WORKER_COUNT` notifications diffusées s'exécutent
simultanément dans chaque processus worker Gunicorn. La valeur par défaut est
`4` ; la valeur effective par défaut pour tout le serveur est donc
`APPRISE_WORKER_COUNT * 4`. Les flux supplémentaires reçoivent le code HTTP
`200` et restent connectés dans une file d'attente ; l'envoi commence
automatiquement lorsqu'un worker se libère. Un envoi continue d'occuper son
emplacement si le client se déconnecte pendant son exécution. Un proxy inverse
peut toujours appliquer ses propres limites de connexions ou de requêtes avant
Apprise API.

:::note
`-N` (`--no-buffer`) indique à `curl` d'afficher chaque événement dès son arrivée plutôt que d'attendre la fermeture de la connexion.
:::

Les notifications stateless sont idéales pour un usage de type « sidecar » lorsque vous ne voulez pas gérer de configuration persistante sur le serveur. Vous devez fournir le paramètre `urls` à chaque requête.

Lorsque l'authentification est activée, utilisez les identifiants administrateur, ou envoyez des `urls` explicites avec les identifiants d'un utilisateur de configuration et l'en-tête `X-Apprise-Config-ID` correspondant. L'accès doit être `user` ; `locked`, `public` et `disabled` ne peuvent pas envoyer de notifications stateless. Pour rester compatible avec l'API Apprise v2, l'en-tête sans `urls` conserve l'envoi stateful avec la configuration enregistrée.

### Requête JSON de Base

La méthode la plus courante consiste à envoyer une charge utile JSON à `/notify`.

**Endpoint :** `POST /notify`

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -d '{
    "urls": "mailto://user:pass@gmail.com",
    "body": "Backup completed successfully.",
    "title": "System Status"
  }' \
  http://localhost:8000/notify
```

### Pièces Jointes

Pour envoyer des pièces jointes, utilisez `multipart/form-data`. L'API accepte les uploads de fichiers classiques ainsi que les URL distantes. Utilisez `attach` comme nom de champ recommandé. Les alias `attachment` et `attachments` sont également acceptés.

Pour les charges utiles JSON qui fournissent des pièces jointes distantes ou encodées, utilisez les mêmes noms de champ.

```bash
# Uploader un fichier local
curl -X POST \
    -F "urls=discord://webhook_id/token" \
    -F "body=See attached log." \
    -F "attach=@/var/log/syslog" \
    http://localhost:8000/notify

# Référencer une URL distante (Apprise la téléchargera puis la transmettra)
curl -X POST \
    -F "urls=discord://webhook_id/token" \
    -F "body=Security Camera Snapshot" \
    -F "attach=http://camera-ip/snapshot.jpg" \
    http://localhost:8000/notify
```

Les notifications stateful vous permettent de simplifier votre code client. Vous stockez une fois sur le serveur les URL complexes, associées à une **clé**, puis votre client référence simplement cette clé.

**Endpoint :** `POST /notify/{KEY}`

### Envoyer vers une Clé

Si vous avez enregistré une configuration sous la clé `my-alerts` :

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -d '{
    "body": "Database connection failed",
    "type": "warning"
  }' \
  http://localhost:8000/notify
```

Lorsque l'authentification est activée, conservez la même URL avec la clé et ajoutez Basic Auth :

```bash
curl -u "user:password" -X POST \
  -H "Content-Type: application/json" \
  -d '{"body": "Database connection failed", "type": "warning"}' \
  http://localhost:8000/notify/my-alerts
```

Une connexion administrateur avec mot de passe uniquement utilise `-u ":password"`.

Un administrateur peut aussi définir un ID de configuration comme `public`. Les appelants publics omettent Basic Auth, mais doivent fournir un tag précis autre que `all`. L'accès public fonctionne uniquement pour les notifications avec état ; les autres points de terminaison restent protégés.

Le mode `disabled` bloque l'accès de l'utilisateur sans supprimer sa configuration ni ses identifiants. Un administrateur peut toujours la gérer et l'utiliser.

### Tags

Les configurations stateful prennent en charge les tags, ce qui vous permet de notifier des sous-groupes spécifiques de vos URL enregistrées.

La valeur passée dans le champ `tag` suit les règles suivantes :

| Valeur `tag`       | Services sélectionnés                        |
| ------------------ | -------------------------------------------- |
| `"TagA"`           | Possède `TagA`                               |
| `"TagA TagB"`      | Possède `TagA` **ET** `TagB`                 |
| `"TagA+TagB"`      | Possède `TagA` **ET** `TagB`                 |
| `"TagA&TagB"`      | Possède `TagA` **ET** `TagB`                 |
| `"TagA,TagB"`      | Possède `TagA` **OU** `TagB`                 |
| `"TagA\|TagB"`     | Possède `TagA` **OU** `TagB`                 |
| `"TagA TagC,TagB"` | Possède (`TagA` **ET** `TagC`) **OU** `TagB` |

```bash
# Notifier les services tagués "devops" OU "admin"
curl -X POST -d '{"tag": "devops,admin", "body": "..."}' ...

# Notifier les services tagués "devops" ET "critical"
curl -X POST -d '{"tag": "devops critical", "body": "..."}' ...

# Notifier les services correspondant à ('comment' ET 'create') OU 'admin'
curl -X POST -d '{"tag": "comment create,admin", "body": "..."}' ...
```

## Mapping du Payload (Hooks)

Parfois, vous ne pouvez pas changer le format du payload envoyé par un outil tiers (par ex. Grafana, Prometheus). L'API Apprise permet de faire correspondre les champs entrants avec les champs compatibles Apprise via des paramètres de requête préfixés par deux-points (`:`).

:::note
Les clés de mapping passent dans la query string et doivent être encodées URL si elles contiennent des caractères spéciaux.
:::

### Règles de Mapping

| Syntaxe                          | Effet                                          |
| -------------------------------- | ---------------------------------------------- |
| `?:incoming_field=apprise_field` | Renomme `incoming_field` vers le champ Apprise |
| `?:incoming_field=`              | Supprime `incoming_field` du payload           |
| `?:apprise_field=literal value`  | Force `apprise_field` à une chaîne fixe        |

**Exemple** — votre outil envoie `{"message": "Server Down", "severity": "high"}`, mais Apprise attend `body` et `type` :

```bash
curl -X POST \
  -d '{"message": "Server Down", "severity": "high"}' \
  "http://localhost:8000/notify/my-alerts?:message=body&:severity=type"
```

### Mapping de Champs Imbriqués

Lorsque le payload entrant utilise des objets imbriqués ou des tableaux, référencez-les côté source de la règle avec une **notation pointée** pour les objets imbriqués et une **notation entre crochets** pour les éléments de tableau. Les deux peuvent être combinés librement.

#### Objets Imbriqués (Notation Pointée)

Utilisez un chemin séparé par des points pour parcourir des dictionnaires imbriqués :

```bash
# Payload provenant d'un outil de supervision :
# { "event": { "title": "CPU spike", "state": "critical" },
#   "component": { "name": "web-server-01" } }
curl -X POST \
  -H "Content-Type: application/json" \
  -d '{"event":{"title":"CPU spike","state":"critical"},"component":{"name":"web-server-01"}}' \
  "http://localhost:8000/notify/my-alerts?:event.title=title&:event.state=type&:component.name=body"
```

#### Éléments de Tableau (Notation entre Crochets)

Ajoutez `[N]` juste après le nom de clé pour déréférencer l'index `N` dans ce tableau. Les indices multiples et le mélange avec la notation pointée sont pris en charge :

```bash
# Payload provenant d'un webhook forum / gestion de projet (ex. Scoold / Para) :
# { "items": [ { "title": "New post", "objectURI": "https://example.com/q/1234" } ] }
curl -g -X POST \
  -H "Content-Type: application/json" \
  -d '{"items":[{"title":"New post","objectURI":"https://example.com/q/1234"}]}' \
  "http://localhost:8000/notify/my-alerts?:items[0].title=title&:items[0].objectURI=body"
```

:::note
`curl` traite les crochets dans les URL comme une syntaxe de globbing ; `-g` (ou `--globoff`) est donc requis lorsque vous utilisez des chemins de mapping tels que `items[0].title`. Gardez l'URL entre guillemets afin que le shell la transmette telle quelle.
:::

Les indices chaînés permettent de traverser des tableaux imbriqués :

```text
# Clé source           Ce à quoi elle correspond
items[0]               premier élément du tableau items
items[0].objectURI     propriété .objectURI du premier élément
```
