Le conteneur API Apprise est hautement configurable via des variables d'environnement.

## Configuration d'Exécution

| Variable                             | Défaut    | Description                                                                                                                                                                                                                                                                                                                                                                                                                          |
| :----------------------------------- | :-------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `APPRISE_STATEFUL_MODE`              | `hash`    | Contrôle le moteur de stockage persistant.<br/>`simple` : enregistre les configurations sous forme de fichiers lisibles (`/config/{KEY}.yaml`). Recommandé pour la plupart des utilisateurs.<br/>`hash` : enregistre les configurations sous forme de hachages indexés. Efficace à grand volume.<br/>`disabled` : désactive entièrement le stockage persistant (mode stateless uniquement). Les valeurs sont insensibles à la casse. |
| `APPRISE_STATELESS_MODE`             | `enabled` | Contrôle les appels `/notify/` sans état.<br/>`enabled` : accepte les requêtes.<br/>`disabled` : rejette les requêtes. Si les deux modes de notification sont désactivés, `/status` indique `degraded`.                                                                                                                                                                                                                              |
| `APPRISE_WORKER_COUNT`               | _(Auto)_  | Nombre de workers Gunicorn. La valeur par défaut est `(2 * CPUs) + 1`. Définissez `1` pour les environnements à faibles ressources.                                                                                                                                                                                                                                                                                                  |
| `APPRISE_WORKER_MAX_REQUESTS`        | `1000`    | Nombre de requêtes traitées par un worker avant son recyclage. Le recyclage libère la mémoire accumulée. Réduisez cette valeur, par exemple à `100`, si vos workers restent actifs longtemps et que la mémoire a tendance à croître.                                                                                                                                                                                                 |
| `APPRISE_WORKER_MAX_REQUESTS_JITTER` | `50`      | Décalage aléatoire ajouté à `APPRISE_WORKER_MAX_REQUESTS` pour éviter que tous les workers redémarrent ensemble.                                                                                                                                                                                                                                                                                                                     |
| `APPRISE_WORKER_TIMEOUT`             | `300`     | Délai d'expiration d'un worker, en secondes.                                                                                                                                                                                                                                                                                                                                                                                         |
| `APPRISE_BASE_URL`                   | _(Aucun)_ | Définissez cette valeur si vous exécutez l'application derrière un proxy inverse sous un sous-chemin, par exemple `/apprise`.                                                                                                                                                                                                                                                                                                        |
| `APPRISE_ADMIN`                      | `no`      | Définissez `yes` pour activer le point de terminaison `/cfg`, ce qui permet d'afficher toutes les clés enregistrées dans l'interface Web. Cela fonctionne **uniquement** si `APPRISE_STATEFUL_MODE` est défini sur `simple`.                                                                                                                                                                                                         |

## Sécurité et Accès

| Variable                   | Défaut               | Description                                                                                                                                                                                                                                                                                                           |
| :------------------------- | :------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `STRICT_MODE`              | `no`                 | Conteneur uniquement. Autorise les routes Apprise connues, renvoie `404` pour les routes inconnues et `405` pour les méthodes non prises en charge, et applique des limites d'authentification renforcées qui renvoient `429` avec `Retry-After`.                                                                     |
| `APPRISE_CONFIG_LOCK`      | `no`                 | Masque le contenu et la gestion des configurations aux utilisateurs ordinaires. Les nouveaux comptes utilisent `locked` par défaut. Un administrateur peut enregistrer `user` ou `public`, mais ces modes se comportent comme `locked` jusqu'à la désactivation de ce réglage. Le choix enregistré n'est pas réécrit. |
| `APPRISE_AUTH_REQUIRED`    | `no`                 | Définissez `yes` pour activer l'authentification. Lorsqu'elle est désactivée, les paramètres d'administration et les connexions de configuration enregistrées sont ignorés. Voir [Authentification et Contrôle d'Accès](../deployment/#authentification-et-contrôle-daccès).                                          |
| `APPRISE_USER`             | _(Aucun)_            | Nom d'utilisateur administrateur facultatif, utilisé uniquement avec `APPRISE_AUTH_REQUIRED=yes`. Il exige `APPRISE_PASSWORD` et ne peut pas contenir de deux-points.                                                                                                                                                 |
| `APPRISE_PASSWORD`         | _(Aucun)_            | Mot de passe administrateur facultatif, utilisé uniquement avec `APPRISE_AUTH_REQUIRED=yes`. Il peut être utilisé sans nom d'utilisateur. Laissez-le non défini pour autoriser uniquement les connexions de configuration existantes.                                                                                 |
| `APPRISE_BASIC_AUTH_REALM` | `Apprise API`        | Nom affiché dans les invites Basic Auth. Il ne modifie pas les identifiants. Utilisez un nom différent pour chaque instance partageant un même hôte.                                                                                                                                                                  |
| `APPRISE_WEB_AUTH_SECRET`  | _(Valeur intégrée)_  | Clé facultative qui signe les connexions Web. Sa modification déconnecte les navigateurs sans déplacer les configurations en mode `hash`.                                                                                                                                                                             |
| `APPRISE_TRUSTED_ORIGINS`  | _(Aucun)_            | Adresses publiques autorisées à effectuer des modifications depuis un navigateur, séparées par des virgules. Utilisez l'adresse complète `scheme://host[:port]`, par exemple `https://apprise.example.com`. Les clients directs comme `curl` ne sont pas affectés.                                                    |
| `ALLOWED_HOSTS`            | `*`                  | Liste, séparée par des espaces, des en-têtes `Host` autorisés.                                                                                                                                                                                                                                                        |
| `APPRISE_DENY_SERVICES`    | _(Liste par défaut)_ | Liste séparée par des virgules des schémas à bloquer. Par exemple, `dbus`, `windows`, `macosx`, `gnome` et `syslog` sont bloqués par défaut dans Docker.                                                                                                                                                              |
| `APPRISE_ALLOW_SERVICES`   | _(Tous)_             | Liste séparée par des virgules des schémas autorisés. Si elle est définie, seuls ces services fonctionneront.                                                                                                                                                                                                         |

### Impact Mémoire du Filtrage des Services

`APPRISE_ALLOW_SERVICES` et `APPRISE_DENY_SERVICES` ne se contentent pas d'activer ou désactiver des schémas. L'API Apprise **évince automatiquement de la mémoire les bibliothèques optionnelles** lorsque tous les plugins qui en dépendent sont désactivés.

Chaque plugin de notification nécessitant une dépendance lourde déclare cette dépendance en interne. Lorsque le dernier plugin utilisant une bibliothèque donnée est désactivé, cette bibliothèque est retirée de l'exécution Python (`sys.modules`), ce qui libère les objets associés. Cela se produit au démarrage, avant la première requête.

**Exemple** — un déploiement qui n'a besoin que de Telegram et NTFY :

```bash
APPRISE_ALLOW_SERVICES=tgram,ntfy
```

Cela désactive tous les autres plugins, ce qui provoque l'éviction de `slixmpp`, `paho`, `gntp`, `smpplib`, ainsi que des wrappers `cryptography`. Combiné avec `APPRISE_WORKER_COUNT=1`, cela permet de ramener un conteneur mono-worker depuis une base typique d'environ 180 MB à environ **145 MB**.

:::note
Ce comportement d'éviction est spécifique à **l'API Apprise**. La bibliothèque Python Apprise, lorsqu'elle est utilisée directement ou intégrée dans des projets tiers, n'évince pas les bibliothèques ; les plugins désactivés deviennent simplement inactifs, et les modules déjà chargés restent en mémoire.
:::

Pour un guide complet sur la réduction de la mémoire conteneur et de la RAM, consultez [Utilisation des Ressources](../../qa/resource-usage/).

## Stockage et Limites

| Variable                         | Défaut | Description                                                                                                        |
| :------------------------------- | :----- | :----------------------------------------------------------------------------------------------------------------- |
| `APPRISE_ATTACH_SIZE`            | `200`  | Taille maximale des pièces jointes, en MB. Définissez `0` pour désactiver les pièces jointes.                      |
| `APPRISE_UPLOAD_MAX_MEMORY_SIZE` | `3`    | Taille maximale, en MB, du corps de requête conservé en mémoire avant déversement sur disque.                      |
| `APPRISE_CONFIG_MAX_LENGTH`      | `512`  | Taille maximale de la charge utile de configuration, en KB. Ne peut pas dépasser `APPRISE_UPLOAD_MAX_MEMORY_SIZE`. |
| `APPRISE_STREAM_MEMORY_SIZE`     | `2`    | Journaux du flux et du résultat conservés en mémoire avant le stockage sur disque, en Mo.                          |
| `APPRISE_STREAM_DISK_SIZE`       | `256`  | Espace disque temporaire accordé à chaque flux et chaque résultat, en Mo.                                          |
| `APPRISE_STREAM_WORKER_COUNT`    | `4`    | Flux actifs par processus worker Gunicorn. Les flux supplémentaires sont mis en attente.                           |
| `APPRISE_RECURSION_MAX`          | `1`    | Profondeur maximale de récursion pour les appels `apprise://` vers d'autres serveurs.                              |

## Paramètres Supplémentaires de l'API Apprise

Le conteneur prend aussi en charge les variables suivantes, qui correspondent directement aux paramètres du serveur.

:::note[À propos de `<BASE_DIR>` dans les valeurs par défaut]
`<BASE_DIR>` **n'est pas** une variable d'environnement : il s'agit du répertoire où l'application API Apprise est installée et exécutée, c'est-à-dire son répertoire de travail. Les chemins relatifs que vous définissez pour ces variables sont eux aussi résolus depuis ce même répertoire. Si vous devez stocker des données en dehors du répertoire d'installation, utilisez un chemin absolu, par exemple `/data/apprise/config`.
:::

## Django et Journalisation

| Variable                         | Défaut              | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| :------------------------------- | :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SECRET_KEY`                     | _(Valeur intégrée)_ | Clé secrète Django. Remplacez toujours cette valeur en production.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `DEBUG`                          | `no`                | Active le mode debug. Prend en charge `yes`, `1`, `true` et autres variantes similaires.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `LOG_LEVEL`                      | `INFO`              | Niveau par défaut des journaux Django, de la console et des notifications. `X-Apprise-Log-Level` peut demander un autre niveau pour une notification sans modifier la sortie de la console.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `TZ`                             | `Etc/UTC`           | Fuseau horaire appliqué à tous les horodatages des journaux. Tout nom de fuseau IANA est accepté, par exemple `America/New_York` ou `Europe/London` — consultez la [liste des fuseaux horaires de la base tz](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones) pour les valeurs valides. Tous les processus du conteneur (journalisation Python, nginx, etc.) héritent directement de `TZ`, de sorte que les horodatages restent cohérents que le conteneur s'exécute en tant que root ou non. Le montage de `/etc/localtime` ou `/etc/timezone` sans définir `TZ` n'est plus pris en charge — définissez `TZ` avec le nom du fuseau souhaité à la place. |
| `ALLOWED_HOSTS`                  | `*`                 | Liste des hôtes autorisés, séparés par des espaces.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `APPRISE_UPLOAD_MAX_MEMORY_SIZE` | `3`                 | Taille maximale, en MB, du corps de requête conservé en mémoire avant que Django ne lève `RequestDataTooBig`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
