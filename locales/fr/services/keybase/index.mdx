## Configuration du compte

Apprise communique directement avec le service Keybase en cours d'execution
localement -- aucun outil en ligne de commande n'est necessaire. L'application
Keybase doit etre installee, vous devez etre connecte et le service doit
tourner en arriere-plan au moment de l'envoi des notifications.

1. Telechargez et installez Keybase depuis <https://keybase.io/download>.
2. Connectez-vous une fois avec `keybase login` ou via l'application de bureau.
3. Laissez l'application Keybase en cours d'execution lors de l'envoi des
   notifications.

:::note
Apprise se connecte directement au processus du service Keybase, et non a un
outil en ligne de commande. Le service doit etre actif (l'application de bureau
ou le demon d'arriere-plan le maintient automatiquement apres la connexion).
:::

## Modes de connexion

Deux modes de connexion sont disponibles, selectionnes via le parametre
`?mode=`.

### Mode socket (defaut)

Apprise se connecte via un socket de domaine Unix dont le chemin est detecte
automatiquement selon la plateforme. C'est le mode par defaut et ne necessite
aucune configuration supplementaire.

| Plateforme | Chemin du socket par defaut |
| ---------- | --------------------------- |
| Linux      | `$XDG_RUNTIME_DIR/keybase/keybased.sock` (ex. `/run/user/1000/keybase/keybased.sock`) |
| macOS      | `~/Library/Group Containers/keybase/Library/keybased.sock` |
| Windows    | `\\.\pipe\keybase.service` |

Vous pouvez remplacer le chemin avec le parametre `?socket=` :

```text
keybase://_/@alice?socket=/run/user/1000/keybase/keybased.sock
```

### Mode TCP

Apprise se connecte via HTTP a un point de terminaison du service Keybase
local. Fournissez l'hote et le port dans l'autorite de l'URL -- l'hote
prend par defaut la valeur `localhost` si omis.

```text
keybase://localhost:3000/@alice
```

Vous pouvez egalement specifier le mode TCP explicitement avec le port via
les parametres de requete :

```text
keybase://_/@alice?mode=tcp&port=3000
```

## Syntaxe

Les syntaxes valides sont les suivantes :

- `keybase://_/@{username}` -- message direct a un utilisateur (mode socket)
- `keybase://_/{teamname}` -- message a une equipe (canal par defaut : `general`)
- `keybase://_/{teamname}%23{channel}` -- message a un canal d'equipe specifique
- `keybase://_/@{user1}/@{user2}/{teamname}%23{channel}` -- plusieurs cibles
- `keybase://localhost:{port}/@{username}` -- mode TCP

Les cibles peuvent egalement etre fournies via le parametre `?to=` :

- `keybase://_/?to=@{username}`
- `keybase://_/?to={teamname}%23{channel}`

:::tip
Les formes courtes (sans le caractere de substitution `_`) sont egalement
acceptees en mode socket :

- `keybase://@{username}` -- message direct
- `keybase://{teamname}` -- message d'equipe
- `keybase://{teamname}%23{channel}` -- canal d'equipe
:::

## Detail des parametres

| Variable | Requis | Description |
| -------- | ------ | ----------- |
| `@username` | \*Oui (au moins une cible) | Nom d'utilisateur Keybase pour un message direct. Prefixer avec `@`. |
| `teamname` | \*Oui (au moins une cible) | Nom de l'equipe Keybase. Ajouter `%23channel` pour un canal specifique. |
| `channel` | Non | Canal d'equipe (topic). Valeur par defaut : `general`. Separer du nom d'equipe avec `%23` dans l'URL. |
| `mode` | Non | Mode de connexion : `socket` (defaut) ou `tcp`. |
| `socket` | Non | Remplacer le chemin du socket Unix (mode socket uniquement). |
| `port` | Non | Numero de port pour le service HTTP Keybase local (mode TCP). |
| `sigkey` | Non | Graine de cle de signature Ed25519 en hexadecimal (64 caracteres) pour la signature Saltpack. Voir ci-dessous. |

## Signature Saltpack des messages

Lorsqu'un `sigkey` est configure, Apprise enveloppe chaque message sortant
dans une **enveloppe de message signe Saltpack v2.0** avant l'envoi. Les
destinataires peuvent verifier la signature avec `keybase verify` ou tout
client Saltpack.

Cette fonctionnalite necessite le paquet Python **PyNaCl** :

```bash
pip install PyNaCl
```

### Etape 1 -- Generer une paire de cles de signature

La cle de signature est une graine Ed25519 aleatoire de 32 octets
representee sous forme d'une **chaine hexadecimale de 64 caracteres**.
Generez-en une avec l'une des methodes ci-dessous.

<Tabs>
<TabItem label="Python">

```python
from apprise.utils.saltpack import AppriseSaltpackController

sk_hex, vk_hex = AppriseSaltpackController.keygen_signing()
print("Cle de signature (garder secrete -- utiliser comme sigkey=) :", sk_hex)
print("Cle de verification (partager avec les destinataires) :", vk_hex)
```

Si vous n'avez besoin que de la graine sans la bibliotheque Apprise :

```python
import secrets
print(secrets.token_hex(32))
```

</TabItem>
<TabItem label="Linux / macOS (bash)">

Via l'utilitaire Apprise :

```bash
python3 -c "
from apprise.utils.saltpack import AppriseSaltpackController
sk, vk = AppriseSaltpackController.keygen_signing()
print('sigkey :', sk)
print('vk     :', vk)
"
```

Ou une commande minimale qui genere uniquement la graine :

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

</TabItem>
<TabItem label="Windows (PowerShell)">

En utilisant Python (si installe) :

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

En utilisant le generateur de nombres aleatoires cryptographique de .NET
(aucun Python requis) :

```powershell
[System.BitConverter]::ToString(
    [System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32)
).Replace("-", "").ToLower()
```

Cette commande utilise le GNA cryptographiquement sur de .NET, disponible
dans Windows PowerShell 5.1 et PowerShell 7+. Aucun module supplementaire
n'est necessaire.

</TabItem>
</Tabs>

Copiez la sortie de 64 caracteres. Cette chaine **est** votre graine de cle
de signature. Conservez-la en securite -- quiconque la possede peut produire
des signatures apparaissant comme venant de vous.

### Etape 2 -- Ajouter la cle a votre URL Apprise

Ajoutez `?sigkey=` suivi de votre chaine hexadecimale de 64 caracteres :

```text
keybase://_/@alice?sigkey=aabbccdd...64hexchars
```

### Etape 3 -- Partager votre cle de verification avec les destinataires

La graine de cle de signature et la cle de verification correspondante
forment une paire prive/publique. Pour permettre aux destinataires de
confirmer l'authenticite de vos messages, partagez la **cle de verification**
(`vk_hex` de l'etape 1).

:::caution
Conservez votre cle de signature en securite. Traitez-la avec le meme soin
qu'un mot de passe. Si elle est compromise, generez une nouvelle paire de cles
et mettez a jour votre URL Apprise ainsi que tous les destinataires possedant
l'ancienne cle de verification.
:::

## Exemples

Envoyer un message direct a un utilisateur (mode socket) :

```bash
apprise -vv -t "Titre" -b "Message" \
    keybase://_/@alice
```

Envoyer un message a une equipe (canal par defaut `general`) :

```bash
apprise -vv -t "Titre" -b "Message" \
    keybase://_/myteam
```

Envoyer un message a un canal d'equipe specifique :

```bash
apprise -vv -t "Titre" -b "Message" \
    "keybase://_/myteam%23dev"
```

Envoyer a plusieurs cibles a la fois :

```bash
apprise -vv -t "Titre" -b "Message" \
    "keybase://_/@alice/@bob/myteam%23general"
```

Envoyer en mode TCP (hote et port explicites) :

```bash
apprise -vv -t "Titre" -b "Message" \
    keybase://localhost:3000/@alice
```

Envoyer avec un chemin de socket personnalise :

```bash
apprise -vv -t "Titre" -b "Message" \
    "keybase://_/@alice?socket=/run/user/1000/keybase/keybased.sock"
```

Envoyer un message signe avec Saltpack :

```bash
# En supposant que sigkey est aabbccdd...64hexchars
apprise -vv -t "Titre" -b "Message" \
    "keybase://_/@alice?sigkey=aabbccdd11223344aabbccdd11223344aabbccdd11223344aabbccdd11223344"
```
