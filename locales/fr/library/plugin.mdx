## Introduction

Les plugins Apprise, aussi appelés **services**, sont des classes Python qui héritent de `NotifyBase`. La façon la plus rapide d'en créer un nouveau consiste à partir d'un plugin fonctionnel proche de votre intégration cible, puis à adapter sa forme d'URL, son parsing et sa logique d'envoi.

## Exceptions

Utilisez les exceptions Apprise afin que les applications puissent traiter les erreurs de manière cohérente.

| Exception                     | Description                                                                                                                 |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `AppriseException`            | La base de toutes les exceptions Apprise. Interceptez-la pour traiter toutes les erreurs Apprise ensemble.                  |
| `AppriseImproperlyConfigured` | Un paramètre obligatoire manque ou n'est pas valide. Utilisez cette exception pour les contrôles du constructeur du plugin. |
| `ApprisePluginException`      | Le plugin a échoué pour une raison sans rapport avec ses paramètres.                                                        |
| `AppriseInvalidData`          | Les données enregistrées ou reçues ne peuvent pas être utilisées en toute sécurité.                                         |
| `AppriseDiskIOError`          | Une opération sur un fichier ou un disque a échoué. Cette exception peut aussi être interceptée avec `OSError`.             |

Importez les exceptions depuis `apprise.exception`. Les applications existantes qui interceptent `TypeError`, `ValueError` ou `AttributeError` restent compatibles avec `AppriseImproperlyConfigured`.

Ce modèle est idéal pour :
- écrire vers une destination locale (`stdout`, fichier, syslog) ;
- prototyper un schéma d'URL avant d'ajouter la couche réseau.

```python
# apprise/plugins/demo.py
from .base import NotifyBase
from ..common import NotifyType
from ..locale import gettext_lazy as _


class NotifyDemo(NotifyBase):
    service_name = _("Apprise Demo Notification")
    protocol = "demo"
    setup_url = "https://appriseit.com/services/demo/"

    # Disable throttling for a purely local plugin
    request_rate_per_sec = 0

    templates = (
        "{schema}://",
    )

    def url(self, *args, **kwargs):
        params = self.url_parameters(*args, **kwargs)
        return "{schema}://?{params}".format(
            schema=self.protocol,
            params=self.urlencode(params),
        )

    def send(self, body, title="", notify_type=NotifyType.INFO, **kwargs):
        self.throttle()
        print(f"{notify_type} - {title} - {body}")
        return True

    @staticmethod
    def parse_url(url):
        # demo:// has no host, so verify_host must be False
        return NotifyBase.parse_url(url, verify_host=False)
```

```python
# apprise/plugins/demo_http.py
import json
import requests

from ..common import NotifyType
from ..exception import AppriseImproperlyConfigured
from ..url import PrivacyMode
from ..utils import parse_bool
from ..locale import gettext_lazy as _
from .base import NotifyBase


class NotifyDemoHTTP(NotifyBase):
    service_name = _("Apprise Demo Notification")
    protocol = "demo"
    secure_protocol = "demos"
    setup_url = "https://appriseit.com/services/demo/"

    templates = (
        "{schema}://{host}/{apikey}",
        "{schema}://{host}:{port}/{apikey}",
        "{schema}://{user}@{host}/{apikey}",
        "{schema}://{user}@{host}:{port}/{apikey}",
        "{schema}://{user}:{password}@{host}/{apikey}",
        "{schema}://{user}:{password}@{host}:{port}/{apikey}",
    )

    template_tokens = dict(
        NotifyBase.template_tokens,
        **{
            "host": {
                "name": _("Hostname"),
                "type": "string",
                "required": True,
            },
            "port": {
                "name": _("Port"),
                "type": "int",
                "min": 1,
                "max": 65535,
            },
            "user": {
                "name": _("Username"),
                "type": "string",
            },
            "password": {
                "name": _("Password"),
                "type": "string",
                "private": True,
            },
            "apikey": {
                "name": _("API Key"),
                "type": "string",
                "private": True,
            },
        },
    )

    def __init__(self, apikey, **kwargs):
        super().__init__(**kwargs)

        self.apikey = apikey
        if not self.apikey:
            raise AppriseImproperlyConfigured(
                f"An invalid API key ({apikey}) was specified."
            )

    @property
    def url_identifier(self):
        """A stable tuple used by url_id() and persistent storage.

        It should uniquely identify the URL configuration so stored/cached data
        does not clobber different configurations.

        Do not include:
        - targets (channels, recipients, endpoints)
        - most GET parameters, unless they fundamentally change upstream behaviour
        """
        default_port = 443 if self.secure else 80
        return (
            self.secure_protocol if self.secure else self.protocol,
            self.user,
            self.password,
            self.host,
            self.port if self.port else default_port,
            str(self.apikey),
        )

    def url(self, privacy=False, *args, **kwargs):
        params = self.url_parameters(privacy=privacy, *args, **kwargs)

        auth = ""
        if self.user and self.password:
            auth = "{user}:{password}@".format(
                user=self.quote(self.user, safe=""),
                password=self.pprint(
                    self.password, privacy, mode=PrivacyMode.Secret, safe=""
                ),
            )
        elif self.user:
            auth = "{user}@".format(user=self.quote(self.user, safe=""))

        default_port = 443 if self.secure else 80
        schema = self.secure_protocol if self.secure else self.protocol
        port = (
            ""
            if self.port is None or self.port == default_port
            else f":{self.port}"
        )

        return "{schema}://{auth}{hostname}{port}/{apikey}?{params}".format(
            schema=schema,
            auth=auth,
            hostname=self.host,
            port=port,
            apikey=self.quote(self.apikey, safe=""),
            params=self.urlencode(params),
        )

    def send(self, body, title="", notify_type=NotifyType.INFO, **kwargs):
        headers = {
            "User-Agent": self.app_id,
            "Content-Type": "application/json",
            "Authorization": f"Bearer {self.apikey}",
        }

        payload = {
            "type": notify_type.value,
            "title": title,
            "body": body,
        }

        self.throttle()

        # prepare our port formatting
        port = f":{self.port}" if self.port else ""

        try:
            r = requests.post(
                f"http://{self.host}{port}",
                data=json.dumps(payload),
                headers=headers,
                verify=self.verify_certificate,
                timeout=self.request_timeout,
                allow_redirects=self.redirects,
            )
            if r.status_code < 200 or r.status_code >= 300:
                return False

        except requests.RequestException:
            return False

        return True

    @staticmethod
    def parse_url(url):
        results = NotifyBase.parse_url(url)
        if not results:
            return results

        try:
            results["apikey"] = NotifyDemoHTTP.split_path(results["fullpath"])[0]
        except IndexError:
            results["apikey"] = None

        return results
```

<TabItem value="targets" label="Cibles multiples">
Ce modèle convient pour :

- Envoyer le même message à plusieurs salons, numéros ou adresses
- Tout service où une cible peut échouer pendant que les autres réussissent

```python
# apprise/plugins/demotargets.py
import requests

from .base import NotifyBase
from ..common import NotifyType
from ..locale import gettext_lazy as _
from ..utils.parse import parse_list


class NotifyDemoTargets(NotifyBase):
    service_name = _("Apprise Demo Targets")
    secure_protocol = "demotargets"
    setup_url = "https://appriseit.com/services/demotargets/"

    notify_url = "https://example.com/api/send"

    templates = (
        "{schema}://{token}/{targets}",
    )

    template_tokens = dict(
        NotifyBase.template_tokens,
        **{
            "token": {
                "name": _("Token"),
                "type": "string",
                "private": True,
                "required": True,
            },
            "targets": {
                "name": _("Targets"),
                "type": "list:string",
            },
        },
    )

    def __init__(self, token, targets=None, **kwargs):
        super().__init__(**kwargs)
        self.token = token
        self.targets = parse_list(targets)

    def send(self, body, title="", notify_type=NotifyType.INFO, **kwargs):
        has_error = False

        for target in self.targets:
            # Cette cible a déjà reçu le message lors d'une tentative
            if self.is_delivered(target):
                continue

            self.throttle()
            r = requests.post(
                self.notify_url,
                data={"to": target, "message": body},
                headers={"Authorization": self.token},
                verify=self.verify_certificate,
                timeout=self.request_timeout,
                allow_redirects=self.redirects,
            )

            if r.status_code != requests.codes.ok:
                self.logger.warning("Failed to notify %s.", target)
                has_error = True
                continue

            self.logger.info("Sent notification to %s.", target)

            # L'enregistrer pour qu'une nouvelle tentative l'ignore
            self.mark_delivered(target)

        return not has_error

    def url(self, privacy=False, *args, **kwargs):
        return "{schema}://{token}/{targets}?{params}".format(
            schema=self.secure_protocol,
            token=self.pprint(self.token, privacy, safe=""),
            targets="/".join(
                NotifyDemoTargets.quote(x, safe="") for x in self.targets
            ),
            params=NotifyDemoTargets.urlencode(
                self.url_parameters(privacy=privacy, *args, **kwargs)
            ),
        )

    def __len__(self):
        return len(self.targets) if self.targets else 1

    @staticmethod
    def parse_url(url):
        results = NotifyBase.parse_url(url, verify_host=False)
        if not results:
            return results

        results["token"] = NotifyDemoTargets.unquote(results["host"])
        results["targets"] = NotifyDemoTargets.split_path(
            results["fullpath"]
        )
        return results
```

## Vue d'Ensemble du Modèle

### Parsing d'URL

Apprise détermine d'abord le `schema://` qui lui a été fourni, puis appelle la méthode `YourPlugin.parse_url()` du plugin de notification pour effectuer le reste du traitement.

En général, le premier appel effectué dans votre fonction `parse_url()` consiste à appeler la méthode parente (issue de `NotifyBase`). Cela permet à Apprise d'extraire les éléments d'URL communs comme `schema`, `host`, `port`, `user`, `password` et `fullpath`. Votre `parse_url()` doit se concentrer sur les éléments spécifiques à votre service, puis renvoyer un `dict` dont les clés correspondent à la signature de votre `__init__()`.

Une règle importante, vérifiée par les tests unitaires, est que les métadonnées de vos templates doivent correspondre proprement aux arguments de `__init__()`, soit directement (même nom), soit via `map_to`.

### Limitation de Débit, Vérification, Redirections et Timeouts

`URLBase` définit la vérification SSL, le comportement des redirections et les timeouts socket communs en tant qu'arguments d'URL. Passez toujours les attributs correspondants dans chaque appel `requests.*` de votre plugin :

- `verify` contrôle `verify_certificate` -- à passer via `verify=self.verify_certificate`
- `redirect` contrôle `redirects` -- à passer via `allow_redirects=self.redirects`
- `rto` contrôle le timeout de lecture socket
- `cto` contrôle le timeout de connexion socket

## Masquer les Secrets dans `url()`

La méthode `url()` de chaque plugin reçoit un indicateur `privacy`. Lorsqu'il vaut `True`, l'URL est destinée à un journal ou à un écran : les mots de passe et les jetons doivent donc être masqués. Passez chaque valeur sensible dans `self.pprint()` et choisissez un mode qui décide de ce qui reste visible :

| Mode                         | Sortie `privacy=True` pour `i-am-a-token` | À Utiliser Pour                                                                           |
| ---------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------- |
| `PrivacyMode.Outer` (défaut) | `i...n`                                   | Jetons, clés d'API et identifiants de webhook. Il en reste assez pour en distinguer deux. |
| `PrivacyMode.Tail`           | `...oken`                                 | Valeurs reconnues à leurs derniers chiffres, comme un numéro de téléphone ou de compte.   |
| `PrivacyMode.Secret`         | `****`                                    | Mots de passe. Rien n'est affiché, pas même la longueur.                                  |

Avec `privacy=False`, `pprint()` renvoie la valeur encodée pour l'URL, comme `self.quote()`. Passez `safe=""` pour les valeurs placées dans le chemin de l'URL, afin qu'un `/` qu'elles contiennent soit lui aussi encodé. Une valeur vide renvoie une chaîne vide en mode `Outer` et `Tail`, tandis que `Secret` renvoie toujours `****`.

```python
from ..url import PrivacyMode


def url(self, privacy=False, *args, **kwargs):
    params = self.url_parameters(privacy=privacy, *args, **kwargs)

    return "{schema}://{user}:{password}@{token}/?{params}".format(
        schema=self.secure_protocol,
        user=self.quote(self.user, safe=""),
        password=self.pprint(
            self.password, privacy, mode=PrivacyMode.Secret, safe=""
        ),
        token=self.pprint(self.token, privacy, safe=""),
        params=self.urlencode(params),
    )
```

| Appel               | Résultat                                  |
| ------------------- | ----------------------------------------- |
| `url()`             | `myservice://joe:pass123@abcdef1234/?...` |
| `url(privacy=True)` | `myservice://joe:****@a...4/?...`         |

Marquez les mêmes valeurs avec `"private": True` dans `template_tokens` ou `template_args`. C'est ce qui indique au [Générateur d'URL](#limportance-du-flag-private) de les masquer, et les [tests unitaires](#tester-votre-plugin) vérifient que rien de ce qui est marqué privé n'apparaît dans l'URL de confidentialité.

## Limites de Débit

### Délai Fixe

Appelez `self.throttle()` juste avant chaque requête de votre plugin. Elle attend juste assez pour qu'au moins `request_rate_per_sec` secondes séparent deux requêtes d'une même instance du plugin.

```python
class NotifyMyService(NotifyBase):
    # The vendor allows one request per second
    request_rate_per_sec = 1.0

    def send(self, body, title="", notify_type=NotifyType.INFO, **kwargs):
        # Always throttle before talking to the server
        self.throttle()
        r = requests.post(...)
```

`NotifyBase` fixe cette valeur à `5.5` secondes, ce qui convient à presque tous les services mais reste lent. Baissez-la si le fournisseur documente une limite plus haute, et mettez `0` pour un plugin local ou pour un plugin qui suit lui-même la limite (voir ci-dessous).

`self.throttle(wait=10)` attend exactement 10 secondes au lieu de l'intervalle habituel. C'est ainsi qu'un plugin respecte une limite que le serveur lui a communiquée.

### Limites Annoncées par le Serveur

Certains services indiquent à quel point vous êtes proche de leur limite, ou combien de temps patienter une fois qu'elle est atteinte. Les plugins qui lisent ces informations utilisent deux attributs d'instance, définis dans `__init__()` :

| Attribut              | Type             | Signification                                                                                                                |
| --------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `ratelimit_remaining` | `float`          | Nombre de requêtes encore permises par le serveur. `0` ou moins signifie que le plugin est bloqué jusqu'à `ratelimit_reset`. |
| `ratelimit_reset`     | `datetime` (UTC) | Moment où le serveur rouvre la fenêtre. Stocké sans fuseau horaire (`.replace(tzinfo=None)`).                                |

Ces attributs ne sont pas intégrés à `NotifyBase`. C'est une convention partagée, alors reprenez ces noms. Discord, Fluxer, Mastodon, Bluesky, Reddit, Revolt et Twitter les utilisent tous, selon l'un de deux styles :

<Tabs>
<TabItem label="En-têtes de Limite (Discord)">

Le serveur envoie `X-RateLimit-Remaining` et `X-RateLimit-Reset` (un horodatage Unix) à chaque réponse. Le plugin les recopie après chaque requête : il sait donc qu'il n'a plus de requêtes disponibles avant de recevoir un `429`.

```python
from datetime import datetime, timedelta, timezone


class NotifyMyService(NotifyBase):
    # The server reports its limits, so skip the fixed delay
    request_rate_per_sec = 0

    # Our clock and the server's may differ slightly; wait a bit longer
    clock_skew = timedelta(seconds=10)

    def __init__(self, **kwargs):
        super().__init__(**kwargs)

        # Not blocked yet
        self.ratelimit_reset = datetime.now(timezone.utc).replace(tzinfo=None)
        self.ratelimit_remaining = 1.0

    def _send(self, payload, rate_limit=1):
        wait = None
        if self.ratelimit_remaining <= 0.0:
            now = datetime.now(timezone.utc).replace(tzinfo=None)
            if now < self.ratelimit_reset:
                wait = abs(
                    (self.ratelimit_reset - now + self.clock_skew)
                    .total_seconds()
                )

        self.throttle(wait=wait)

        r = requests.post(...)

        try:
            # Remember what the server told us for the next request
            self.ratelimit_remaining = float(
                r.headers.get("X-RateLimit-Remaining")
            )
            self.ratelimit_reset = datetime.fromtimestamp(
                int(r.headers.get("X-RateLimit-Reset")), timezone.utc
            ).replace(tzinfo=None)

        except (TypeError, ValueError):
            # Headers missing or unreadable; keep the old values
            pass

        if r.status_code == requests.codes.too_many_requests and rate_limit > 0:
            # Try once more. The check at the top now waits for the reset.
            return self._send(payload, rate_limit=rate_limit - 1)

        # ...normal status handling
```

</TabItem>
<TabItem label="Retry-After (Fluxer)">

Le serveur ne dit rien tant que la limite n'est pas atteinte. Il répond alors `429` avec un en-tête `Retry-After` qui donne le nombre de secondes à attendre. Le plugin se bloque pendant cette durée, réessaie, puis lève le blocage dès qu'un envoi réussit.

```python
from datetime import datetime, timedelta, timezone


class NotifyMyService(NotifyBase):
    # The server reports its limits, so skip the fixed delay
    request_rate_per_sec = 0

    # Wait at least this long after a 429, even without Retry-After
    default_delay_sec = 1.0

    def __init__(self, **kwargs):
        super().__init__(**kwargs)

        # Not blocked yet
        self.ratelimit_reset = datetime.now(timezone.utc).replace(tzinfo=None)
        self.ratelimit_remaining = 1.0

    def _send(self, payload, rate_limit=1):
        wait = None
        if self.ratelimit_remaining <= 0.0:
            now = datetime.now(timezone.utc).replace(tzinfo=None)
            if now >= self.ratelimit_reset:
                # The block has passed; clear it
                self.ratelimit_remaining = 1.0
            else:
                wait = (self.ratelimit_reset - now).total_seconds()

        self.throttle(wait=wait)

        r = requests.post(...)

        if r.status_code == requests.codes.too_many_requests:
            delay = self.default_delay_sec
            try:
                delay = float(r.headers.get("Retry-After"))
            except (TypeError, ValueError):
                pass

            # Block ourselves until the server is ready again
            now = datetime.now(timezone.utc).replace(tzinfo=None)
            self.ratelimit_remaining = 0.0
            self.ratelimit_reset = now + timedelta(
                seconds=max(self.default_delay_sec, delay)
            )

            if rate_limit > 0:
                # The check at the top now waits out the delay
                return self._send(payload, rate_limit=rate_limit - 1)

            return False

        # ...normal status handling
```

</TabItem>
</Tabs>

Les deux styles partagent quelques règles :

- Mettez `request_rate_per_sec = 0`, sinon le délai fixe s'ajoute à celui du serveur.
- Ne réessayez un `429` qu'un nombre limité de fois. Le compteur `rate_limit` ci-dessus permet un seul nouvel essai, pour qu'un serveur qui refuse sans cesse ne bloque pas le plugin indéfiniment.
- Fermez les fichiers ouverts (pièces jointes) avant de rappeler `_send()`.
- Ce nouvel essai est distinct de l'option d'URL `retry=` de l'utilisateur, qui répète un envoi complet après un échec.

## Images de Notification

Apprise fournit une icône pour chaque type de notification (info, succès, avertissement et échec). Définir `image_size` indique à Apprise quelle taille envoyer à votre service. Laissez `None` et votre plugin n'en envoie jamais.

| Valeur                   | Taille    |
| ------------------------ | --------- |
| `NotifyImageSize.XY_32`  | 32 x 32   |
| `NotifyImageSize.XY_72`  | 72 x 72   |
| `NotifyImageSize.XY_128` | 128 x 128 |
| `NotifyImageSize.XY_256` | 256 x 256 |

Choisissez la taille la plus proche de ce qu'affiche le service. Trois méthodes renvoient l'icône d'un type de notification :

| Méthode                        | Renvoie                            | À Utiliser Quand                                                    |
| ------------------------------ | ---------------------------------- | ------------------------------------------------------------------- |
| `self.image_url(notify_type)`  | Une URL publique vers l'icône      | Le service télécharge l'image lui-même.                             |
| `self.image_path(notify_type)` | Le chemin de l'icône sur le disque | Une bibliothèque locale a besoin d'un fichier (fenêtres de bureau). |
| `self.image_raw(notify_type)`  | L'icône sous forme de `bytes`      | Vous envoyez ou intégrez l'image vous-même.                         |

Chacune renvoie `None` si `image_size` n'est pas défini ou si l'utilisateur a désactivé les images dans son `AppriseAsset` : vérifiez donc toujours le résultat. La plupart des plugins proposent aussi une option d'URL `image=` (associée à `include_image`) pour que l'utilisateur puisse désactiver l'icône URL par URL :

```python
from ..common import NotifyImageSize


class NotifyMyService(NotifyBase):
    image_size = NotifyImageSize.XY_256

    def send(self, body, title="", notify_type=NotifyType.INFO, **kwargs):
        payload = {"text": body}

        image_url = self.image_url(notify_type)
        if self.include_image and image_url:
            payload["icon"] = image_url
```

## `url_identifier`

La propriété `url_identifier` sert à distinguer une configuration d'une autre de manière unique, afin que les données en cache ou persistantes n'écrasent pas des configurations différentes. C'est aussi ainsi qu'Apprise génère un identifiant unique cohérent et stable à partir d'une URL.

- **Incluez** le schéma ou protocole, les identifiants et l'identité de connexion amont.
- **Excluez** les cibles (canaux, destinataires, endpoints).
- **Excluez** la plupart des paramètres GET. N'incluez un paramètre GET que s'il change fondamentalement le comportement de la communication amont.

Si deux URL décrivent la même configuration effective, elles devraient générer le même `url_identifier`, et donc le même `url_id()`.

Notez également l'interrupteur de stockage :

- Si `store=no` est défini, `url_id()` renvoie `None`, et `url()` doit conserver `store=no` dans sa sortie.

Exemple :

```python
@property
def url_identifier(self):
    return (
        self.secure_protocol if self.secure else self.protocol,
        self.user,
        self.password,
        self.host,
        self.port if self.port else (443 if self.secure else 80),
    )
```

:::note
`url_identifier` donne concrètement à l'URL que vous avez définie une clé unique réutilisable permettant de l'identifier. Cette même clé est utilisée pour choisir un emplacement de fichier unique pour le moteur de stockage persistant, afin d'éviter qu'un cache n'écrase celui d'une autre instance.
:::

## Activation du Stockage Persistant (`storage_mode`)

Si votre plugin effectue des consultations répétées en amont (jetons OAuth, appels de découverte, identifiants résolus, vérifications de capacités), vous devriez envisager d'activer le stockage persistant. Cela vous évitera de refaire ces vérifications plus tard et accélérera le plugin.

Pour l'activer, définissez un `storage_mode` au niveau de la classe :

```python
from apprise.common import PersistentStoreMode

class NotifyMyService(NotifyBase):
    # ...
    storage_mode = PersistentStoreMode.AUTO
```

Recommandations :

- Utilisez `PersistentStoreMode.AUTO` pour la plupart des plugins.
- Utilisez `PersistentStoreMode.FLUSH` uniquement lorsque les données mises en cache sont coûteuses à recalculer et que vous voulez une meilleure durabilité.
- Conservez le comportement par défaut (mémoire uniquement) si votre plugin ne doit jamais persister d'état, ou si le cache apporte peu de bénéfice.

Combiné à un `url_identifier` bien formé (identité de configuration uniquement), cela permet à plusieurs instances visant des destinataires différents de réutiliser le même cache pour une même configuration amont.

## Cibles et \_\_len\_\_

`__len__()` permet aux auteurs et aux outils de savoir combien de cibles sont chargées dans un plugin.

- Si vous ne la redéfinissez pas, l'implémentation de base renvoie `1`.
- Redéfinissez-la dans les plugins qui prennent en charge plusieurs cibles, généralement en renvoyant `len(self.targets)` avec un minimum de `1`.

## Livraison vers plusieurs cibles

Si `send()` parcourt plusieurs cibles, enregistrez chaque réussite. Une nouvelle tentative ne contacte alors que les cibles qui ont échoué.

```python
for target in self.targets:
    if self.is_delivered(target):
        continue

    if not self._post(target, body):
        has_error = True
        continue

    self.mark_delivered(target)
```

`is_delivered()` vérifie si une cible a déjà reçu le message. Appelez `mark_delivered()` seulement après que la cible l'a accepté.

La clé identifie la cible, par exemple un numéro de téléphone, un identifiant de salon, un jeton ou une adresse e-mail. Les listes et dictionnaires sont également acceptés.

Remarques :

- Les deux méthodes ne font rien lorsque `retry=0`, la valeur par défaut.
- Chaque partie d'un message découpé est suivie séparément.
- Une partie pour laquelle `send()` a renvoyé `True` n'est pas renvoyée lors d'une nouvelle tentative. Votre propre suivi sert uniquement à choisir qui reçoit une partie qui a partiellement échoué.
- Le suivi est supprimé à la fin de la notification.
- Un élément envoyé une seule fois pour toute la notification, comme une image, utilise `per_message=True` afin de ne pas être répété pour chaque partie :

```python
image_key = ("image", target)
if not self.is_delivered(image_key, per_message=True):
    if self.send_image(target):
        self.mark_delivered(image_key, per_message=True)
```

- Pour les lots, utilisez une clé stable comme `(catégorie, position_du_lot)` afin de distinguer chaque lot.
- Si une cible nécessite plusieurs requêtes, ajoutez la position de la requête à la clé et enregistrez chaque requête seulement après sa réussite.
- Si vous comptez les réussites, comptez aussi une cible ignorée :

```python
if self.is_delivered(target):
    delivered += 1
    continue
```

Seules les boucles d'envoi ont besoin de ce suivi. Les boucles qui préparent les données, découpent un message ou regroupent les destinataires d'une même requête n'en ont pas besoin.

Pour partager d'autres valeurs entre les tentatives, consultez **Conserver un état entre les tentatives** ci-dessous.

## Conserver un état entre les tentatives

`remember()` et `recall()` partagent une valeur entre les tentatives d'une même notification. Elle disparaît à la fin de la notification, afin que la suivante reparte de zéro.

Utilisez-les pour les valeurs qu'une nouvelle tentative doit réutiliser, comme un identifiant de requête, une référence de fichier envoyé ou un jeton temporaire.

| Situation                       | Comportement                                                                                                          |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Les tentatives sont activées    | Chaque tentative de cette notification relit ce qu'une tentative précédente a conservé.                               |
| Les tentatives sont désactivées | `remember()` ne conserve rien et `recall()` renvoie sa valeur par défaut. Aucune tentative ultérieure ne la relirait. |

:::note
N'utilisez pas `self.store` pour un état limité aux nouvelles tentatives. Il survit à la notification et impose une expiration arbitraire, tandis que `remember()` est vidé automatiquement à la fin.
:::

<Tabs>
<TabItem label="Clé d'idempotence">

Une clé d'idempotence empêche un service d'agir deux fois. Réutilisez la clé d'origine lorsqu'une requête restée sans réponse est relancée.

```python
from hashlib import sha256
from json import dumps
from uuid import uuid4

data = dumps(payload)

# Une notification peut envoyer plusieurs requêtes : nommons celle-ci
fingerprint = sha256(data.encode("utf-8")).hexdigest()

key = self.recall(fingerprint)
if key is None:
    key = str(uuid4())
    self.remember(fingerprint, key)

headers["Idempotency-Key"] = key
```

</TabItem>
<TabItem label="Éviter de refaire un travail">

Tout traitement coûteux qu'une nouvelle tentative ne devrait pas refaire, comme l'envoi d'un fichier avant le message qui s'y réfère.

```python
def _media_id(self, attachment):
    """Envoyer le fichier une fois par notification, pas par tentative."""

    # per_message, car un seul envoi sert tous les morceaux d'un
    # message découpé
    media_id = self.recall(attachment.path, per_message=True)
    if media_id is None:
        media_id = self._upload(attachment)
        if media_id:
            self.remember(attachment.path, media_id, per_message=True)

    return media_id
```

</TabItem>
<TabItem label="Avec le suivi de livraison">

Utilisez `remember()` et `recall()` pour partager l'état des nouvelles tentatives. Utilisez `is_delivered()` et `mark_delivered()` pour suivre les cibles qui ont déjà accepté la notification.

```python
def send(self, body, title="", notify_type=NotifyType.INFO,
         attach=None, **kwargs):
    """Envoyer le fichier une fois, puis joindre les cibles en attente."""

    has_error = False

    # Envoyé lors de la première tentative, puis réutilisé par les autres
    media_id = self._media_id(attach) if attach else None

    for target in self.targets:
        # Acceptée lors d'une tentative précédente : on la laisse
        if self.is_delivered(target):
            continue

        if not self._post(target, body, media_id):
            has_error = True
            continue

        self.mark_delivered(target)

    return not has_error
```

</TabItem>
</Tabs>

Remarques :

- Les deux méthodes sont inertes lorsque les tentatives sont désactivées : le chemin par défaut `retry=0` ne coûte rien et ne demande aucune précaution de votre part.
- Chaque morceau conserve sa propre valeur, même si son contenu est identique à celui d'un autre. Utilisez `per_message=True` uniquement pour un état partagé par toute la notification, comme un fichier envoyé une fois et utilisé par chaque morceau.
- Lorsqu'une notification effectue plusieurs requêtes, utilisez une clé distincte pour chacune. Une empreinte du corps de la requête convient généralement.
- Les types de clés restent distincts : `1`, `"1"` et `["1"]` ne partagent donc pas leur état.

### `runtime_deps()` : Indice d'Éviction Mémoire

Si votre plugin **importe conditionnellement une bibliothèque tierce lourde**, redéfinissez aussi `runtime_deps()` pour indiquer au gestionnaire de plugins quels noms de paquets de premier niveau ont été chargés.

```python
class NotifyMyService(NotifyBase):
    # ...

    @staticmethod
    def runtime_deps():
        return ("mylibrary",)
```

La valeur renvoyée est un **tuple de noms de paquets de premier niveau importables** : la même chaîne que vous passeriez à `import`, et non le nom du paquet pip (par exemple `"paho"` pour `paho-mqtt`).

Le [gestionnaire de notifications](./extending/notification-manager/#library-eviction) maintient un compteur de références pour chaque bibliothèque déclarée. Lorsque tous les plugins qui utilisent une bibliothèque donnée sont désactivés et que `N_MGR.evict_on_disable` vaut `True`, le gestionnaire retire cette bibliothèque, ainsi que tous ses sous-modules, de `sys.modules`, libérant ainsi les objets Python associés en mémoire.

- Renvoyez la valeur par défaut de la classe de base `()` (tuple vide) si votre plugin n'a pas de dépendances runtime optionnelles justifiant une éviction.
- Les sous-modules sont gérés automatiquement ; ne déclarez que le nom de premier niveau.
- Cela est distinct de `requirements`, qui nomme des paquets pip à des fins de reporting humainement lisible. `runtime_deps()` nomme les paquets importables pour la gestion mémoire à l'exécution.

:::note
`runtime_deps()` n'est utile que lorsque la bibliothèque est chargée conditionnellement (importée uniquement si le plugin est actif). Si votre plugin importe toujours la bibliothèque au chargement du module, l'éviction n'a pas d'effet pratique, car le module est déjà résident.
:::

Autres règles importantes :

- `choice:bool` n'est pas autorisé ; utilisez `bool` à la place.
- `regex` doit être un 2-tuple `(pattern, option)`, et les motifs doivent commencer par `^` et se terminer par `$`.
- Si `required` ou `private` ne sont pas fournis, ils valent `False` par défaut.
- Si `values` est un dictionnaire, il est converti en liste de clés.

## Modèles d'Organisation des Templates

Ces exemples se concentrent uniquement sur la manière dont les métadonnées de template, `__init__()` et `parse_url()` s'articulent.

class MyPlugin(NotifyBase):

class MyPlugin(NotifyBase):

Si vous définissez un `template_token`, `template_arg` ou `template_kwarg`, vous devez le prendre en charge dans `parse_url()`, car le `dict` renvoyé par `parse_url()` sert à initialiser la classe.

```python
import re

from apprise.utils import parse_bool  # example helper

class MyPlugin(NotifyBase):
    ## Plugin variables here (intentionally omitted)

    secure_protocol = "foobar"

    templates = ("{schema}://{token}",)

    template_tokens = dict(
        NotifyBase.template_tokens,
        **{
            "token": {
                "name": _("Auth Token"),
                "type": "string",
                "private": True,
                "required": True,
                "regex": (r"^[a-z0-9]+$", "i"),
            },
        },
    )

    template_args = dict(
        NotifyBase.template_args,
        **{
            "image": {
                "name": _("Include Image"),
                "type": "bool",
                "default": True,
                "map_to": "include_image",
            },
        },
    )

    def __init__(self, host, token, include_image, *args, **kwargs):
        # Rest of code here
        super().__init__(host=host, *args, **kwargs)

    @staticmethod
    def parse_url(url):
        results = NotifyBase.parse_url(url, verify_host=False)

        # Token is in the host position in this example
        results["token"] = MyPlugin.unquote(results["host"])

        results["include_image"] = parse_bool(results["qsd"].get(
            "image", MyPlugin.template_args['image']['default']))

        return results
```

Plusieurs noms de jetons peuvent pointer vers le même argument `__init__()` via `map_to`. Les tests vérifient que toutes les valeurs de `map_to` correspondent à des arguments valides de `__init__()` ou à l'un des mots-clés reconnus par le framework.

```python
import re

from apprise.utils import parse_bool  # example helper

class MyPlugin(NotifyBase):
    ## Plugin variables here (intentionally omitted)

    secure_protocol = "foobar"

    templates = ("{schema}://{targets}",)

    template_tokens = dict(
        NotifyBase.template_tokens,
        **{
            "target_user": {
                "name": _("Target User"),
                "type": "string",
                "map_to": "targets",
            },
            "target_stream": {
                "name": _("Target Stream"),
                "type": "string",
                "map_to": "targets",
            },
            "targets": {
                "name": _("Targets"),
                "type": "list:string",
                "delim": ("/",),
            },
        },
    )

    template_args = dict(
        NotifyBase.template_args,
        **{
            "to": {
                "alias_of": "targets",
            },
        },
    )

    def __init__(self, targets, *args, **kwargs):
        # Rest of code here
        super().__init__(*args, **kwargs)

    @staticmethod
    def parse_url(url):
        results = NotifyBase.parse_url(url, verify_host=False)

        # Store our targets
        results["targets"] = [MyPlugin.unquote(results["host"])]
        results["targets"].extend(MyPlugin.split_path(results["fullpath"]))

        # Support an alias that is easier to express in YAML
        if "to" in results["qsd"] and len(results["qsd"]["to"]):
            results["targets"] += list(
                filter(
                    bool,
                    re.split(r"[ \t\r\n,#\\/]+", MyPlugin.unquote(results["qsd"]["to"])),
                )
            )

        return results
```

### Référence des Directives de Template

Les tests unitaires imposent les clés autorisées et les contraintes de type.

| Directive    | Utilisée dans        | Signification                                                                                                                          |
| :----------- | :------------------- | :------------------------------------------------------------------------------------------------------------------------------------- |
| `name`       | tokens, args, kwargs | Libellé lisible humainement, généralement enveloppé dans `gettext_lazy()`.                                                             |
| `type`       | tokens, args         | Type de valeur, validé par l'expression régulière stricte des types.                                                                   |
| `required`   | tokens, args         | Marque une entrée comme obligatoire. Si omis, vaut `False`.                                                                            |
| `private`    | tokens, args         | Marque une entrée comme sensible. Si omis, vaut `False`.                                                                               |
| `default`    | args                 | Valeur par défaut utilisée quand l'URL ne précise rien. Requise pour les args `bool`.                                                  |
| `values`     | types `choice`       | Valeurs autorisées pour les types `choice`, requises pour tout type `choice:*`.                                                        |
| `min`, `max` | int, float           | Bornes pour les types numériques.                                                                                                      |
| `regex`      | tokens, args         | Regex de validation, toujours sous la forme `(pattern, option)` avec ancrage `^...$`.                                                  |
| `delim`      | types `list`         | Délimiteurs utilisés pour découper les listes, requis pour les types `list:*`.                                                         |
| `prefix`     | kwargs               | Requis pour les kwargs, doit être l'un de `:`, `+` ou `-`.                                                                             |
| `map_to`     | tokens, args, kwargs | Associe une clé à un autre nom d'argument `__init__()`. Les tests vérifient qu'il s'agit d'un argument valide ou d'un mot-clé reconnu. |
| `alias_of`   | args, kwargs         | Déclare un alias pour un token ou argument existant, souvent pour faciliter la configuration YAML.                                     |
| `group`      | tokens               | Utilisé pour regrouper plusieurs jetons mappés dans une entrée de type liste.                                                          |

Les cibles `map_to` reconnues par le framework incluent les champs d'URL courants et les arguments partagés, même s'ils ne figurent pas dans le `__init__()` de votre plugin, comme `user`, `password`, `host`, `port`, `schema`, `fullpath`, `format`, `overflow`, `emojis`, `tz`, `verify`, `cto`, `rto` et `store`.

### Règles de Mapping

Apprise utilise les métadonnées de vos templates comme un contrat, et les tests en garantissent la cohérence :

- Chaque élément de `template_tokens` doit correspondre à un véritable argument de `__init__()`, soit directement (même clé), soit via `map_to`.
- Les alias (`alias_of`) sont autorisés dans les args et kwargs, mais pas dans les tokens.
- Chaque `alias_of` doit pointer vers un vrai token ou arg, et ne peut pas simplement se pointer lui-même, sauf s'il existe aussi dans les tokens.
- Pour les entrées kwargs, `prefix` est obligatoire et doit être l'un de `:`, `+` ou `-`.

### Règle d'Héritage de `alias_of`

Les entrées alias ne doivent **jamais** redéclarer des propriétés héritées de leur cible. Les clés suivantes sont interdites sur toute entrée contenant `alias_of` :

`private`, `type`, `required`, `regex`, `default`, `min`, `max`, `map_to`, `prefix`, `group`

Ces propriétés sont résolues à l'exécution en suivant la chaîne d'alias. Des consommateurs comme le [générateur d'URL](../url-builder/) les lisent depuis la cible, et non depuis l'alias lui-même. Les seuls ajouts autorisés aux côtés de `alias_of` sont :

| Clé supplémentaire | Quand elle est autorisée                                                                                            |
| :----------------- | :------------------------------------------------------------------------------------------------------------------ |
| `name`             | Requise lorsque `alias_of` liste **plusieurs** cibles, afin de fournir un libellé de regroupement pour l'interface. |
| `delim`            | Autorisée lorsque la cible aliasée est de type `list:*`, afin de surcharger le ou les délimiteurs.                  |

Approches valides :

1. Alias simple : `alias_of` uniquement

   ```python
   "t": {"alias_of": "token"},
   ```

1. Alias multiples : `alias_of` + `name` pour le libellé de regroupement

   ```python
   "tok": {
       "name": _("Token"),
       "alias_of": ("access_token", "token_a", "token_b"),
   },
   ```

1. Alias de liste avec surcharge du délimiteur

   ```python
   "to": {
       "alias_of": "targets",
       "delim": (",", " "),
   },
   ```

Des propriétés supplémentaires en dehors de celles identifiées ci-dessus ne peuvent pas être utilisées. Par exemple, ceci n'est pas valide :

```python
# do NOT redeclare inherited properties
"t": {
    "alias_of": "token",
    "private": True,  # <-- This should have been defined in what is being inherited
},
```

### Exigences d'Aller-Retour

Deux fonctions doivent travailler ensemble :

- `parse_url()` doit extraire chaque argument exposé via `template_args` et `template_kwargs`.
- `url()` doit émettre une URL capable de recréer le même objet, et doit générer le même `url_identifier` lorsqu'il est réinstancié.

## Référence du Schéma de Template

Ce tableau documente les directives les plus courantes prises en charge par `template_tokens`, `template_args` et `template_kwargs`.

| Directive  | Utilisée dans        | Signification                                                                                                   |
| :--------- | :------------------- | :-------------------------------------------------------------------------------------------------------------- |
| `name`     | tokens, args, kwargs | Libellé lisible humainement, généralement enveloppé dans `gettext_lazy()`.                                      |
| `type`     | tokens, args         | Type : `string`, `bool`, `int`, `float`, `email`, `choice:<type>` ou `list:<type>`.                             |
| `required` | tokens, args         | Marque une entrée comme obligatoire pour l'initialisation ou la validation.                                     |
| `default`  | args                 | Valeur par défaut utilisée quand l'URL ne précise rien. Requise pour les types `bool`.                          |
| `private`  | tokens, args         | Marque une valeur comme sensible et destinée à être masquée dans les vues de confidentialité.                   |
| `regex`    | tokens, args         | Un 2-tuple `(pattern, flags)` utilisé pour valider les valeurs. Les motifs doivent être ancrés avec `^` et `$`. |
| `values`   | types `choice`       | Valeurs autorisées pour les types `choice:*`. Si un `default` est fourni, il doit appartenir à `values`.        |
| `delim`    | types `list`         | Délimiteurs autorisés pour les types `list:*`.                                                                  |
| `prefix`   | kwargs               | Requis pour les entrées kwargs ; définit le préfixe d'injection `:`, `+` ou `-`.                                |
| `map_to`   | tokens, args, kwargs | Associe la clé de directive à un autre nom d'argument `__init__()`.                                             |
| `alias_of` | args, kwargs         | Fournit un nom alternatif se comportant exactement comme un autre token ou argument.                            |

### `templates`

- Un tuple de motifs d'URL (chaînes) montrant les formes valides.
- Utilisez `{schema}` dans les templates, et gardez des jetons cohérents d'un template à l'autre.

Il s'agit à la fois de documentation et de métadonnées structurées pouvant être utilisées par les outils pour décrire les formes d'URL prises en charge.

### `template_tokens`

Variables issues de la structure centrale de l'URL, comme :

```text
schema://credentials/direction/?options=
         |                   |
         | variables here    |
```

### `template_args`

Les args décrivent les arguments de query string. `NotifyBase` fournit déjà `format`, `overflow`, `emojis`, `store` et `tz`. `URLBase` fournit déjà `verify`, `rto` et `cto`.

Modèles fréquents :

- utilisez `alias_of` pour ajouter des synonymes ;
- utilisez `map_to` pour faire correspondre des noms d'arguments orientés utilisateur avec les paramètres de votre `__init__()` ;
- utilisez `default` pour documenter clairement le comportement.

### `template_kwargs`

Les kwargs servent aux arguments préfixés pouvant apparaître plusieurs fois, typiquement pour l'injection clé/valeur :

- `+` est souvent utilisé pour les headers ;
- `-` est souvent utilisé pour les paramètres d'URL ;
- `:` est souvent utilisé pour les champs supplémentaires du payload.

Chaque entrée `template_kwargs` exige un `prefix` et un `name`, et ces informations sont aussi exposées dans le [générateur d'URL](../url-builder/) sous la forme d'un tableau **Paramètres Personnalisés** où les utilisateurs peuvent ajouter autant de lignes clé/valeur qu'ils le souhaitent.

```python
template_kwargs = dict(
    NotifyBase.template_kwargs,
    **{
        "headers": {
            "name": _("HTTP Header"),
            "prefix": "+",
        },
        "params": {
            "name": _("GET Parameter"),
            "prefix": "-",
        },
        "payload": {
            "name": _("Payload Extra"),
            "prefix": ":",
        },
    },
)
```

Dans une URL, cela ressemble à : `?+X-Custom-Header=foo&-debug=1&:extra=bar`

## Requirements Et Dépendances Optionnelles

Si votre plugin nécessite des paquets supplémentaires, déclarez-les dans `requirements` afin qu'Apprise puisse indiquer ce qui est requis ou recommandé.

Exemple :

```python
from ..locale import gettext_lazy as _

requirements = {
  "details": _("This plugin requires cryptography for message signing."),
  "packages_required": ["cryptography>=42"],
  "packages_recommended": ["orjson>=3"],
}
```

## Prise en Charge des Pièces Jointes

Les plugins qui prennent en charge les pièces jointes **doivent** déclarer explicitement cette prise en charge en définissant l'attribut de classe suivant :

```python
class NotifyExample(NotifyBase):
    attachment_support = True
```

Une fois activée, les pièces jointes sont fournies au plugin sous la forme d'une liste d'objets `AppriseAttachment`. Ces objets abstraient l'accès aux fichiers et peuvent reposer sur des fichiers locaux, des données en mémoire ou des ressources HTTP distantes.

Les détails complets sur la gestion des pièces jointes, le cycle de vie, les limites de taille et les modèles d'implémentation courants sont documentés ici :

- [Pièces Jointes](./attachments.mdx)

Il est fortement recommandé aux auteurs de consulter cette documentation avant d'implémenter cette prise en charge, car une gestion incorrecte peut facilement entraîner une consommation mémoire excessive ou des envois échoués.

## Intégration avec le Générateur d'URL

Le [générateur d'URL Apprise](../url-builder/) construit son formulaire entièrement à partir des métadonnées exportées par votre plugin. Des métadonnées bien formées offrent une expérience plus propre et conviviale.

### Checklist de Qualité pour le Générateur d'URL

| Élément à définir                            | Pourquoi c'est important                                                                                                           |
| :------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------- |
| `service_name`                               | Affiché comme nom du service dans les résultats de recherche.                                                                      |
| `service_url`                                | Alimente le lien "Site du service" à côté du formulaire.                                                                           |
| `setup_url`                                  | Alimente le lien "Guide de configuration" pour les instructions pas à pas.                                                         |
| `name` sur chaque token/arg                  | Apparaît comme libellé du champ du formulaire. Sans lui, la clé brute est affichée.                                                |
| `private: True` sur les secrets              | Rend le champ comme un mot de passe avec bouton d'affichage, et empêche la valeur de fuiter dans la barre d'adresse du navigateur. |
| `required: True` sur les tokens obligatoires | Marque les champs d'un astérisque (`*`) et bloque la génération d'URL tant qu'ils ne sont pas remplis.                             |
| `regex` sur les tokens validés               | Fournit des indications de format côté client (non imposées dans le navigateur, mais exposées dans les métadonnées du schéma).     |
| `default` sur les args optionnels            | Affiché comme texte indicatif dans les listes déroulantes et les champs numériques.                                                |
| `templates` ordonnés du simple au complexe   | Le générateur d'URL utilise par défaut le template le plus complexe afin que tous les champs soient visibles dès le départ.        |

### Ordre des Templates

Le générateur d'URL choisit par défaut le template **le plus complexe** (celui qui contient le plus de champs `{token}`). À mesure que l'utilisateur remplit des champs, il bascule vers le template le plus simple qui couvre tous les jetons renseignés.

Ordonnez votre tuple `templates` du plus simple au plus complexe :

```python
templates = (
    "{schema}://{token}",                           # simplest, no targets
    "{schema}://{token}/{targets}",                 # adds optional targets
    "{schema}://{botname}@{token}/{targets}",       # most complex
)
```

### L'Importance du Flag `private`

Marquez chaque clé d'API, jeton, mot de passe ou secret avec `"private": True` dans `template_tokens` comme dans `template_args`. Le générateur d'URL :

1. rend le champ comme un mot de passe avec un bouton d'affichage ;
2. affiche `••••••` dans l'URL assemblée à la place de la vraie valeur ;
3. exclut la valeur de la barre d'adresse du navigateur afin que les liens partagés n'exposent jamais les secrets.

Les entrées alias (`alias_of`) **héritent** du flag `private` de leur cible : ne le redéclarez pas sur l'alias.

### `service_url` vs `setup_url`

| Attribut      | Rôle                                                                                                                                                                                                                                                                                                                |
| :------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `service_url` | Lien vers la page d'accueil du fournisseur ou du produit amont (par exemple `https://discord.com/`). Affiché comme "Site du service" dans le générateur d'URL.                                                                                                                                                      |
| `setup_url`   | Lien vers le guide d'intégration spécifique à Apprise sur `appriseit.com` (par exemple `https://appriseit.com/services/discord/`). Affiché comme "Guide de configuration". Vous pouvez créer ou mettre à jour cette documentation dans le [dépôt de documentation Apprise](https://github.com/caronc/apprise-docs). |

Les deux devraient toujours être définis. Les plugins génériques ou purement locaux (par exemple MQTT, notifications Windows) peuvent omettre `service_url` s'il n'existe pas d'URL amont pertinente.

## Format et Dépassement

`NotifyBase` fournit des options d'URL communes comme `format`, `overflow`, `emojis` et le stockage persistant (`store`). Un plugin doit normalement les réutiliser au lieu de définir ses propres variantes.

Pendant l'envoi, `body_format` représente le format final que le plugin doit transmettre. `body_passthrough=True` signifie que l'appelant n'a déclaré aucun format source : Apprise ignore donc la conversion et la réparation du dialecte. Cela ne désactive pas les limites, le dépassement, l'échappement, l'encodage du transport ni la construction de la charge utile.

Le framework gère les limites ordinaires en caractères ainsi que les modes `upstream`, `truncate` et `split`. Un plugin soumis à une limite en octets, à de l'échappement, à plusieurs représentations du corps ou au coût du chiffrement doit calculer son budget à partir de la charge utile finale et la vérifier après conversion.

Ne supposez pas qu'un contenu pass-through quelconque peut être découpé sans risque. Un document JSON, du texte chiffré, une signature ou un balisage inconnu peut devenir invalide. Respectez le mode de dépassement demandé, mais considérez le découpage comme une solution au mieux et évitez les réparations propres à un format lorsque `body_passthrough` vaut `True`.

## Tester Votre Plugin

Apprise vise une couverture de tests de 100 %, donc chaque plugin est livré avec un fichier `tests/test_plugin_<nom>.py`. L'essentiel du travail est fait par `AppriseURLTester`. Vous lui donnez une liste d'URL et ce que chacune doit faire. Pour chaque URL, il :

1. Charge l'URL et vérifie que la bonne classe (ou la bonne erreur) est renvoyée.
2. Reconstruit l'URL avec `url()` et vérifie qu'elle se charge comme le même service.
3. Vérifie que `url(privacy=True)` masque toutes les valeurs marquées `private`.
4. Envoie une notification à travers une bibliothèque `requests` simulée et vérifie le résultat.

La limitation de débit est désactivée pendant ces tests : une valeur élevée de `request_rate_per_sec` ne les ralentit pas.

```python
import requests

from apprise.exception import AppriseImproperlyConfigured
from apprise.plugins.myservice import NotifyMyService

from helpers import AppriseURLTester

apprise_url_tests = (
    # No token given
    (
        "myservice://",
        {
            "instance": AppriseImproperlyConfigured,
        },
    ),
    # A working URL; check how it prints with privacy on
    (
        "myservice://joe:pass123@abcdef1234",
        {
            "instance": NotifyMyService,
            "privacy_url": "myservice://joe:****@a...4",
        },
    ),
    # The server answers 500
    (
        "myservice://joe:pass123@abcdef1234",
        {
            "instance": NotifyMyService,
            "response": False,
            "requests_response_code": requests.codes.internal_server_error,
        },
    ),
    # The connection fails outright
    (
        "myservice://joe:pass123@abcdef1234",
        {
            "instance": NotifyMyService,
            "test_requests_exceptions": True,
        },
    ),
)


def test_plugin_myservice_urls():
    """URLs load, print and send as expected."""
    AppriseURLTester(tests=apprise_url_tests).run_all()
```

Le dictionnaire de chaque URL accepte les clés suivantes. Omettez celles dont vous n'avez pas besoin.

| Clé                        | Défaut                                     | Ce Qui Est Vérifié                                                                                                              |
| -------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `instance`                 | (obligatoire)                              | La classe attendue au chargement de l'URL, ou l'exception qu'elle doit lever. `None` signifie que l'URL ne doit pas se charger. |
| `privacy_url`              | non vérifié                                | Le début de `url(privacy=True)`. Seul le début est comparé : omettez la chaîne de requête.                                      |
| `url_matches`              | non vérifié                                | Une expression régulière que `url()` doit satisfaire.                                                                           |
| `self`                     | non vérifié                                | Un `dict` d'attributs et des valeurs qu'ils doivent avoir après le chargement, par exemple `{"token": "abcdef1234"}`.           |
| `response`                 | `True`                                     | Ce que `notify()` doit renvoyer.                                                                                                |
| `notify_response`          | identique à `response`                     | Remplace `response` pour le seul appel `notify()` simple.                                                                       |
| `attach_response`          | identique à `notify_response`              | Ce que `notify()` doit renvoyer lorsqu'une pièce jointe est envoyée.                                                            |
| `requests_response_code`   | `200`, ou `404` si `response` vaut `False` | Le code HTTP renvoyé par le serveur simulé.                                                                                     |
| `requests_response_text`   | vide                                       | Le corps renvoyé par le serveur simulé. Un `dict` est envoyé en JSON.                                                           |
| `test_requests_exceptions` | `False`                                    | Mettez `True` pour que chaque requête lève une erreur de connexion, et vérifier que le plugin la gère.                          |
| `notify_type`              | `NotifyType.INFO`                          | Le type de notification à envoyer.                                                                                              |
| `include_image`            | `True`                                     | Mettez `False` pour envoyer avec les images désactivées dans l'asset.                                                           |
| `check_attachments`        | `True`                                     | Mettez `False` pour ignorer l'envoi avec pièce jointe.                                                                          |
| `fields_round_trip`        | `True`                                     | Mettez `False` pour ne pas vérifier que les champs de l'URL reconstruisent la même URL.                                         |
| `storage_mode`             | `memory`                                   | Le mode de stockage persistant avec lequel charger le plugin.                                                                   |
| `pdb`                      | `False`                                    | Mettez `True` pour s'arrêter dans le débogueur Python juste avant le chargement de cette URL.                                   |

`AppriseURLTester` couvre les cas courants. Un comportement qu'il ne peut pas atteindre, comme un nouvel essai après un `429` ou une connexion en plusieurs étapes, mérite sa propre fonction de test qui remplace directement `requests.post` (ou `get`) et inspecte les appels. Inspirez-vous des tests existants d'un plugin qui fonctionne comme le vôtre. Consultez [Exécuter les Tests](../../contributing/core/#exécuter-les-tests) pour savoir comment les lancer.
