`AppriseAsset` définit le **contexte global d'exécution** d'une session Apprise.

Il ne se limite pas à l'image de marque ou au thème. Une instance d'asset influence le comportement de :

- tous les plugins de notification ;
- tous les threads d'envoi ;
- le stockage persistant et le matériel de clé ;
- les limites de sécurité globales (masquage des journaux et protection contre la récursion).

Dans la plupart des cas, un asset est créé une seule fois puis passé à `Apprise(...)` lors de son instanciation.

```python
from apprise import Apprise, AppriseAsset

asset = AppriseAsset(app_id="Mon application", theme="default")
apobj = Apprise(asset=asset)
```

Si aucun asset n'est fourni, Apprise en crée un par défaut.

## Cycle de vie et portée

- créé une seule fois, en général au démarrage de l'application ;
- partagé entre tous les plugins chargés et le traitement de configuration ;
- destiné à être considéré comme immuable pendant toute la durée de vie d'une instance `Apprise`.

Modifier un asset après l'avoir lié à `Apprise` peut produire des résultats incohérents d'un plugin à l'autre.

## Initialisation de l'objet

`AppriseAsset.__init__()` fournit des arguments nommés pour le stockage, les
délais d'attente, les limites de messages et d'autres réglages partagés.
Utilisez toujours le nom documenté du constructeur, comme `timezone=`,
`service_timeout=` ou `payload_max_size=`. Ces arguments valident les valeurs
avant de les appliquer.

Les arguments du constructeur Python et les clés YAML `asset:` sont des
interfaces distinctes. Certains réglages sont accessibles aux applications
par `AppriseAsset(...)`, mais volontairement indisponibles dans la
configuration YAML.

## Valeurs par défaut et référence des champs

Ce tableau documente les **vraies valeurs par défaut** issues de l'implémentation, ainsi que l'endroit où chaque champ est utilisé.

| `app_id`             | `str`             |                           `Apprise` | En-têtes de plugins, noms de clés | Utilisé comme identifiant applicatif lisible et comme nom par défaut pour la génération de clés PGP. |

| `theme`              | `str`             |                           `default` | Résolution d'URL/chemin d'icônes  | Pilote la substitution `{THEME}` lors de la recherche d'icônes.                                      |

### Stockage persistant

| Champ           | Type                  | Défaut | Utilisé par                  | Notes                                                                                                |
| --------------- | --------------------- | -----: | ---------------------------- | ---------------------------------------------------------------------------------------------------- |
| `storage_path`  | `str`                 | `None` | `None`                       | Racine de `PersistentStore`. Si absent, Apprise fonctionne uniquement en mémoire pour ces fonctions. |
| `storage_mode`  | `PersistentStoreMode` | `auto` | Comportement PersistentStore | `auto`, `flush`, `memory`.                                                                           |
| `storage_idlen` | `int`                 |    `8` | Génération d'espaces nommés  | Contrôle la longueur des répertoires de namespace générés.                                           |
| `storage_salt`  | `bytes`               |  `b""` | Génération d'espaces nommés  | Fournit un salage facultatif ; les chaînes sont encodées avec `encoding`.                            |

### Gestion du matériel de clé

| Champ         | Type   | Défaut | Utilisé par    | Notes                                                                                                                                                                                                                                                                                          |
| ------------- | ------ | -----: | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pgp_autogen` | `bool` | `True` | Contrôleur PGP | Quand `True` et que le stockage persistant est configuré, génère une paire de clés RSA-2048 (`{localpart}-pub.asc` + `{localpart}-prv.asc`) la première fois qu'aucune clé n'est trouvée. S'applique uniquement à `pgp=encrypt` -- l'étape opportuniste de `pgp=sign` ne génère jamais de clé. |
| `pem_autogen` | `bool` | `True` | Contrôleur PEM | Active la génération automatique de clés PEM si le stockage le permet et qu'aucune clé n'est fournie.                                                                                                                                                                                          |

#### Détails de la génération automatique PGP

Quand `pgp_autogen = True`, Apprise génère **les deux** clés (publique et privée) lors du premier envoi `pgp=encrypt` où aucune clé n'est trouvée :

- `{localpart}-pub.asc` -- clé publique RSA-2048, utilisée pour chiffrer les messages sortants
- `{localpart}-prv.asc` -- clé privée RSA-2048, découverte automatiquement par le mode `pgp=sign`

`{localpart}` est dérivé de l'adresse From de l'expéditeur (tout ce qui précède le `@`, en minuscules).

L'amorçage est donc automatique : configurez `pgp=encrypt` une fois avec le stockage persistant, laissez le premier envoi générer les deux clés, puis passez à `pgp=sign` -- la clé privée sera découverte depuis le même répertoire de stockage, sans paramètre `pgpprv=`.

Pour désactiver la génération automatique globalement :

```python
from apprise import AppriseAsset

asset = AppriseAsset(
    storage_path="/var/lib/apprise",
    pgp_autogen=False,
)
```

Avec `pgp_autogen = False`, aucune paire de clés n'est créée automatiquement. Apprise passe à la méthode de découverte suivante (WKD ou un chemin `pgppub=` explicite) et échoue l'envoi si aucune clé n'est trouvée.

### Limites de sécurité

| Champ                      | Type             |         Défaut | Utilisé par                      | Notes                                                                                                                                                                                                                                       |
| -------------------------- | ---------------- | -------------: | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `http_redirects`           | `bool`           |         `True` | Tous les plugins HTTP            | Quand `True` (par défaut), les plugins suivent les redirections 3xx, conformément au comportement de la bibliothèque requests. Définir à `False` pour désactiver le suivi des redirections globalement sans toucher aux URLs individuelles. |
| `secure_logging`           | `bool`           |         `True` | Pipeline de journalisation       | Ajoute un coût pour masquer les secrets dans les logs ; recommandé de le laisser activé.                                                                                                                                                    |
| `payload_max_size`         | `int`            |            `0` | Formatage/découpage des messages | Limite facultative sur la taille combinée du titre et du corps avant formatage. `0` la désactive. S'applique à tous les modes `overflow=`.                                                                                                  |
| `payload_buffer_threshold` | `int`            |           `10` | Formatage/découpage des messages | Un titre ou un corps de cette longueur ou moins peut rester entier ; voir [Plafond de taille des messages](#plafond-de-taille-des-messages).                                                                                                |
| `payload_min_buffer`       | `int`            |           `25` | Formatage/découpage des messages | Caractères réservés à l'autre côté avant de conserver le côté court en entier ; voir [Plafond de taille des messages](#plafond-de-taille-des-messages).                                                                                     |
| `timezone`                 | `str` / `tzinfo` | fuseau système | Comportement temporel            | Définit le fuseau horaire utilisé par les plugins qui génèrent des horodatages. Accepte un nom IANA comme `"America/Toronto"` ou un objet `tzinfo`. YAML accepte `timezone` ou son alias `tz`.                                              |

<TabItem value="identity" label="Identité et image">

Configure l'instance Apprise avec une image de marque personnalisée.

```python
from apprise import AppriseAsset

asset = AppriseAsset(
    app_id="StatsBot",
    app_desc="Service d'agrégation de métriques",
    app_url="https://example.com",
)
```

</TabItem>

<TabItem value="concurrency" label="Concurrence">

Désactive l'envoi concurrent et force un envoi séquentiel des notifications.

```python
from apprise import AppriseAsset

# Forcer l'envoi séquentiel (pas de concurrence)
asset = AppriseAsset(async_mode=False)
```

</TabItem>

<TabItem value="timeout" label="Délai par Service">

Donne à chaque service de la session le même budget de temps, au lieu des 60
secondes par défaut. Voir [Résultats de notification](/library/results/) pour
savoir comment un service qui dépasse son délai vous est signalé en retour.

```python
from apprise import Apprise, AppriseAsset

# Donne 10 secondes à chaque service (toutes tentatives comprises)
# avant qu'Apprise n'abandonne et ne signale un TIMEOUT
asset = AppriseAsset(service_timeout=10)

apobj = Apprise(asset=asset)
apobj.add("slack://tokenA/tokenB/tokenC")

# Cet appel a également son propre plafond de 30 secondes, en plus du
# budget de 10 secondes par service de l'asset -- le délai le plus
# court l'emporte
apobj.notify(body="Alerte urgente", timeout=30)
```

</TabItem>

<TabItem value="plugins" label="Plugins personnalisés">

Lorsque `plugin_paths` est défini, la détection des modules a lieu pendant l'initialisation de l'asset.

```python
from apprise import AppriseAsset

asset = AppriseAsset(
    plugin_paths=[
        "/opt/apprise/plugins",
        "/srv/myapp/apprise_plugins",
    ]
)
```

</TabItem>

<TabItem value="storage" label="Stockage persistant">

Contrôle le cache sur disque et l'état persistant des plugins.

```python
from apprise import AppriseAsset
from apprise.common import PersistentStoreMode

asset = AppriseAsset(
    storage_path="/var/lib/apprise",
    storage_mode=PersistentStoreMode.AUTO,
    storage_idlen=12,
    storage_salt="my-namespace-salt",
)
```

`storage_salt` peut être de type `bytes` ou `str`. Les chaînes sont encodées avec l'`encoding` de l'asset.

</TabItem>

## Résolution d'icônes et d'images

Apprise résout les icônes à l'aide de masques configurables.

```python
asset = AppriseAsset(
    image_path_mask="/icons/{THEME}/{TYPE}-{XY}{EXTENSION}",
    image_url_mask="https://cdn.example.com/{TYPE}-{XY}{EXTENSION}",
)
```

| Jeton         | Description                     |
| ------------- | ------------------------------- |
| `{THEME}`     | Thème actif                     |
| `{TYPE}`      | info, success, warning, failure |
| `{XY}`        | Taille de l'image               |
| `{EXTENSION}` | Extension de fichier            |

## Contrôles de sécurité

### Redirections HTTP

Par défaut, Apprise suit les redirections HTTP 3xx, conformément au comportement
de la bibliothèque requests sous-jacente. Si vous souhaitez empêcher la
transmission des en-têtes personnalisés et des identifiants vers des destinations
différentes de l'URL d'origine, vous pouvez désactiver globalement le suivi des
redirections :

```python
asset = AppriseAsset(http_redirects=False)
```

Les URLs individuelles peuvent toujours remplacer la valeur par défaut de
l'asset via le paramètre d'URL `redirect=` :

```text
# Remplacement par URL, indépendamment du réglage de l'asset
schema://token/?redirect=yes
schema://token/?redirect=no
```

### Journalisation sécurisée

Lorsqu'elle est activée, les secrets sont masqués dans toutes les sorties de journal.

```python
asset = AppriseAsset(secure_logging=True)
```

La désactiver est fortement déconseillé en dehors d'environnements isolés.

### Plafond de taille des messages

`payload_max_size` définit la limite du message, c'est-à-dire le budget total
de caractères (`N`) pour le titre et le corps avant le formatage ou le
découpage. La valeur `0` désactive cette limite. Si le titre et le corps
tiennent déjà dans `N`, Apprise les laisse inchangés.

```python
asset = AppriseAsset(payload_max_size=100000)
```

Trois réglages fonctionnent ensemble lorsque le contenu dépasse `N` :

| Réglage                    | Défaut | Rôle                                                                            |
| -------------------------- | ------ | ------------------------------------------------------------------------------- |
| `payload_max_size`         | `0`    | Définit `N`, le budget total. `0` désactive la limite.                          |
| `payload_buffer_threshold` | `10`   | Un titre ou un corps aussi court peut être conservé en entier.                  |
| `payload_min_buffer`       | `25`   | Espace que l'autre côté doit conserver avant de garder le côté court en entier. |

Avec les valeurs par défaut, un message trop volumineux est résolu dans cet
ordre :

1. **Un côté est vide :** l'autre reçoit tout le budget.
2. **Un côté est court :** un titre de 10 caractères ou moins reste entier
   si le corps peut conserver 25 caractères, ou toute sa longueur s'il est
   plus court. La même règle vérifie ensuite si le corps est court. Si les
   deux sont admissibles, le titre est vérifié en premier.
3. **Sinon :** le titre et le corps se partagent `N` selon leurs longueurs
   d'origine. Lorsque `N` permet de représenter les deux, chacun conserve au
   moins un caractère.

Par exemple, un titre de 20 caractères et un corps de 18 caractères avec
`N=20` se répartissent environ 10/10. Une limite plus petite peut encore
produire un fragment court, mais elle ne favorise pas un côté lorsque les
deux peuvent être représentés.

Les utilisateurs de la bibliothèque peuvent modifier les deux réglages lors
de la création de l'asset :

```python
asset = AppriseAsset(
    payload_max_size=100000,
    payload_buffer_threshold=10,
    payload_min_buffer=25,
)
```

Avec `payload_min_buffer=0`, aucune place n'est réservée : un côté court
admissible peut donc utiliser toute la limite.

Le formatage et l'échappement peuvent ensuite ajouter quelques caractères.
La limite s'applique à tous les modes `overflow=`, y compris `upstream`.

## Limites des fichiers de configuration

YAML prend volontairement en charge moins de réglages d'asset que le
constructeur Python. Les contrôles numériques comme `service_timeout`,
`payload_max_size`, `payload_buffer_threshold` et `payload_min_buffer`
doivent être fournis par leurs arguments nommés dans `AppriseAsset(...)`.
Les chemins de plugins et les réglages de stockage sont également contrôlés
par l'application afin qu'un fichier de configuration ne puisse ni charger
du code ni rediriger le stockage persistant.

`timezone` est pris en charge dans YAML et peut aussi utiliser l'alias `tz` :

```yaml
asset:
  timezone: America/Toronto # ou : tz: America/Toronto
```
